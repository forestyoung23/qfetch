# 客户端操作异常恢复

仅在实际客户端操作失败或无法观察结果时读取。直接恢复当前业务步骤，不另做能力测试。

区分能力缺失与权限问题：

- `Computer Use is unavailable for this node_repl session`一类宿主错误，表示本会话的控制能力不可用；不等于macOS未授权。核对一次宿主支持的启用方式后仍不可用则停止，不反复导入SDK、猜测API、探测broker或内部端口。
- 只有窗口标题、菜单和空的内容树不算能观察文件列表。按客户端流程恢复窗口后，辅助功能仍不能读取正文时，可使用当前工具允许的截图与输入能力。
- `could not create image from display/rect`只证明该次截图失败；权限、显示会话或捕获后端的原因尚未确定。不能据此声称“授权已登记”“重启后一定生效”。用户完成必要授权或重启后只复测一次，以实际可用结果决定能否继续。
- 工具及宿主技能的边界优先于通用恢复建议；禁止使用的AppleScript、JXA或其他UI后端不作为替代路径。不要为一次下载临时编写Swift/JXA截图器、安装图形桥接依赖或读取TCC数据库来扩展诊断。

从首次客户端操作异常开始，同一故障共用最多两轮、3分钟的主动恢复预算（等待用户授权不计入）。一轮是“重新定位/激活实际窗口 → 必要时退出全屏 → 使用允许的观察通道重读 → 重试当前动作一次”；换工具或换会话继续同一故障不自动重置预算。目录选择阶段出现新故障时也遵守两轮、3分钟上限。正常排队、传输和完成核对不受此恢复时限限制。

两条允许的观察路径都不可用，或恢复预算耗尽时，保存已确认的阶段、最后错误、未提交/已提交/提交结果不明和下一步所需条件，停止本次下载操作。需要用户处理时只提出与证据相符的一项操作，不承诺该操作必定修复。后续只有观察到能力恢复、用户明确要求重新诊断或提供新证据时才重试；不把重新搜索资源作为客户端故障的修复方法。
