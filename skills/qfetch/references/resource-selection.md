# 资源自动选择

在转存或提交下载前执行。用户明确指定的文件、版本和质量要求优先；本文件的默认分辨率与体积取舍只适用于电影等视频，不套用于软件、文档和其他资源。用户已指定具体文件或已有原下载任务时核验复用，不为了比较版本重新搜索；仅提供含多个版本的分享链接时，在分享内按本规则选择。

## 合格候选

先核对作品名称、年份、完整正片、用户要求的版本、语言、字幕及播放兼容条件，排除错片、预告、花絮、枪版、屏摄和失效分享。默认最低选择1080p，不因只有一个资源而自动下载720p及以下版本；用户明确指定其他分辨率时按其要求执行。用户明确要求的属性无法核实时，不视为合格，继续查找。

以实际分享文件列表、完整文件名和可读取的元数据核验，不只看Google摘要或来源页标题。默认按4K（2160p）→2K（本技能指1440p）→1080p划分档位，不能仅凭“2K”宣传字样将1080p归入1440p。分辨率无法判定时先补查当前来源的文件信息；仍无法判定则保留为未验证候选，不参与默认分辨率排序。分辨率标签只是选择依据，不代表实际画质已经通过播放验证。

同一分享中的不同版本分别作为候选；同一文件的重复分享不算多个版本。结合文件名、大小和版本信息去重，证据不足时不能声称文件内容相同。对候选保留来源、文件名、分辨率、大小及其精确/估算状态、要求核验结果和淘汰原因，不保存凭据或提取码。

默认视频用于Jellyfin片库，MKV仅作为条件相当时的封装偏好，MP4等满足要求的格式仍为合格候选。以实际分享文件列表中的完整文件名核验扩展名（不区分大小写），有元数据时交叉核对；来源页标题写有MKV但分享文件无法确认时，不能标记为已核验MKV。MKV后缀不证明画质更好、编码兼容或可以直接播放；仍按可核验信息判断视频编码、音轨和字幕与目标设备的兼容性，未知项如实记录。

## 选择顺序

**10GB是多个合格候选之间的取舍参考，不是下载上限。** 使用十进制10GB，即10,000,000,000字节；来源显示GiB时先换算，不把10GiB当作10GB。没有精确大小时可以按可信约数保守判断；边界不明或大小未知时不能认定为≤10GB，也不能编造字节数。

| 本轮核验结果 | 自动动作 |
|---|---|
| 没有合格候选 | 在剩余检索预算内继续查找；预算结束仍没有则报告未找到，不下载不合格文件 |
| 只有一个合格候选 | 直接选择，允许超过10GB；必须符合下节的检索结束条件，不能将首个发现的文件直接认定为唯一资源 |
| 有多个合格候选，存在≤10GB的版本 | 在≤10GB的候选中按4K→2K→1080p选择最高分辨率 |
| 有多个合格候选，所有版本均超过10GB | 选择最低分辨率档位中的合格版本，允许超过10GB；只有4K时仍可选择4K |
| 有多个合格候选，没有可确认≤10GB的版本，且部分大小未知 | 先在剩余预算内补查大小；结束时仍未知则按最低已确认分辨率档位选择，并明确大小未精确核验 |

同档多个候选，依次比较来源及质量信息的可信程度、字幕与目标设备兼容性的核验完整度，再选择较小的文件；上述条件相当时优先已核验的MKV，仍相同则选择最先核验通过的一项。MKV偏好不覆盖上表的分辨率与10GB取舍，不为MKV降低分辨率、牺牲字幕或播放兼容性，也不因格式偏好选择更大的文件。不因多个画质版本请求用户选择，也不把体积更大直接等同于画质更好。

选择后仍必须检查目标盘和客户端缓存盘的实际可用空间。允许超过10GB不代表可以忽略空间不足；大小未知时按客户端显示值保守估算，无法判断空间是否足够则报告阻碍，不盲目提交。只转存和下载最终选择的文件，不先把所有候选下载到本地再比较。

## 检索结束与交接

- Google查询、来源页访问和分享核验共用[资源检索](web-search.md)的5分钟、6次查询、10个来源页预算，不为每个分辨率重新计时。先查当前分享中已有的版本，再决定是否需要继续Google检索。
- 优先搜索4K，先尝试带`mkv`的查询，无合格结果时去掉格式限制；发现4K超过10GB或未找到合格4K时，在预算内继续寻找2K与1080p，并保留已发现的大文件作为兜底，不直接淘汰。格式偏好不增加预算，不为每档各自重复整套查询；查询须按阶段推进，避免把全部查询次数用在4K或MKV。
- 找到核验通过且≤10GB的4K时，可提前结束并选择，包括合格MP4；不为等待MKV延长检索。只有较低分辨率候选或仅有超出10GB的候选时，继续使用剩余预算查找替代版本。
- 达到任一预算上限，或已检查完本轮Google结果中的相关候选且没有新的有效查询线索时，结束检索并对已核验候选执行上表。此时“只有一个”仅指本轮检索范围内的结果，不代表全网仅有一个资源。
- Google访问、登录授权等环境阻碍不等于检索自然结束；按对应流程报告或等待处理，不能把访问失败解释为不存在其他候选。
- 选择结果交给客户端流程前，简短说明版本、大小、选择理由与重要未验证项，例如“本轮仅核验到一个合格4K版本，大小18GB，按唯一候选规则下载”。用户已给出明确要求时，不自行改成默认版本。

## 选择示例

以下均假设作品及其他必要条件已核验通过，检索已结束，磁盘空间充足；GB为十进制单位。

| 已核验的不同版本 | 选择结果 |
|---|---|
| 只有4K 18GB | 下载4K 18GB |
| 同一个4K 18GB文件的两个已确认重复分享 | 按一个候选处理，下载4K 18GB |
| 4K 9GB、2K 7GB、1080p 4GB | 下载4K 9GB |
| 4K 18GB、2K 8GB、1080p 5GB | 下载2K 8GB |
| 4K 18GB、2K 12GB、1080p 11GB | 下载1080p 11GB |
| 4K 18GB、2K 12GB，无1080p | 下载2K 12GB |
| 只有1080p 14GB | 下载1080p 14GB |
| 同等可信程度、字幕和兼容条件的4K MKV 8GB与4K MP4 8GB | 优先MKV |
| 4K MP4 9GB、1080p MKV 5GB | 下载4K MP4，不为MKV降低分辨率 |
| 4K MKV 18GB、4K MP4 9GB | 下载4K MP4，遵守10GB取舍 |
| 只有合格4K MP4 9GB | 可提前结束并下载，不等待MKV |
| 只有不符合用户要求的版本 | 继续查找；预算结束仍无合格候选则不下载 |
