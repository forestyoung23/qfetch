# 两项流水执行

用于多资源请求。默认最多一个客户端未完成任务A，加一个正在检索或已核验待提交的预备项B；不同时下载两项，不建立无限预备队列。下载由客户端后台继续，Agent交替观察A与检索B，所有客户端输入、目录选择和转存操作串行完成，不让多个操作者同时控制窗口。

## 清单与启动

按作品身份去重，保留指定的不同版本。条件型榜单请求先确定来源、统计日期、排名口径及明确作品清单；身份有歧义时澄清。本技能不包含榜单获取器。

每项使用独立目录及候选记录。Agent维护状态：未执行、检索中、待提交、下载中、完成、失败、受阻，附来源、保存目录及最后观察时间。跨会话先核对本地记录及客户端原任务；不能仅凭历史状态认定已提交或完成。

先完成本会话客户端自检，并将A推进至客户端任务已出现、目标目录正确且观察到实际传输进展；排队、提交结果不明或模态对话框尚未关闭时，先处理A，不启动B的检索。

## 重叠与交接

1. A传输期间，检索并核验B，允许准备候选记录，不提前提交B的下载。共享桌面上一次只执行一个工具操作；切回客户端时重新取得窗口及控件。
2. 按[客户端观察规则](client-workflow.md#观察暂停与恢复)检查A。检索每次工具返回后检查观察时间，距上次观察达到60秒时先检查A，再发起下一次检索调用；不要启动明知会使观察间隔显著超出的长调用。工具意外超时后先观察A，不声称期间持续监控。
3. B沿用[检索预算](web-search.md#关键词与搜索预算)，观察A、切换窗口的耗时也计入B原预算，不暂停或重置。B核验成功后停在待提交，不继续搜索C或重复核验B。
4. A显示完成时，先执行[完成核对](local-checks.md#完成核对)，然后重新核对B分享可用性、网盘查重和空间，按单文件流程转存、准备、提交B。B观察到实际传输进展后，才能检索C。A的本地完成核对失败时先处理该项，不能直接释放下载位置。
5. B没有合格资源时标记失败，可顺次尝试下一个未执行项作为新的B；任意时刻只保留一个预备项，每项独立预算。A完成而B仍在检索时，继续B原预算，不重新搜索。

## 空间与阻碍

预备项选择后，按物理卷检查空间。同一目标卷的可用空间应覆盖A尚需分配空间与B完整文件大小，并为每个未完成项留64MiB余量；缓存卷单独计入对应需求，同一卷不能重复使用同一份余量。没有可靠的A剩余分配量时，保守按A完整大小预留，不从临时文件逻辑大小推算。B只有约数时使用有依据的保守上界；无法估算则仅保留候选，不宣称空间已通过。

预留只是本轮计划，不是操作系统空间锁。B提交前重新检查实时空间并运行`prepare`；A已经完成后，其文件占用已反映在剩余空间中，不再次预留A。空间不足时停止预备与后续提交，保留已有任务；不删除文件或暂停A腾空间。

A发生暂停、失败或达到客户端规则的无进展检查阈值时停止检索B，按客户端规则处理；不因一次取整百分比不变判定停滞。若A明确为单项失败且原任务已不再传输，可保留其文件、记录失败并继续B；原任务仍在传输、排队或状态不明时，不新增下载。失败与传输状态冲突时完整刷新并核对详情一次，仍冲突则报告状态不明并结束主动轮询。登录、客户端、目标盘等共性阻碍未解除时停止流水；不停止已在后台运行的正常任务。等待用户授权时不声称仍在主动监控。

最终逐项汇总完成、失败、受阻和未执行，保留未完成项的原任务、目录及下一步条件。

## 验证范围

两项上限是当前约束，不自动扩大并发。场景推演可验证交接规则；实际效果需用两个已授权文件验证：A传输期间成功核验B、A完成并落盘后才提交B、空间复查通过、两项均无重复任务且最终完成。未执行该实测时明确报告，不沿用单文件测试声称流水已通过验收。
