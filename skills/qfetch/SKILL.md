# 夸克下载

## 下载执行边界（必须遵守）

本任务的文件下载、暂停与恢复只能直接操作夸克客户端。官方`quarkclouddrive`技能仅用于账号查询、文件检索、元数据读取和分享转存，以及这些操作所需的安装与授权；其`download`命令及下载指引不适用于QFetch流程。读取或安装官方技能后，仍须遵守此分工。

禁止尝试CLI下载、获取下载直链、网页/API下载，或登录网页版网盘后点击“下载”来唤起客户端；不能先试其他方式、失败后才改用客户端。公开网页仍可用于Google检索、来源与分享核验及官方授权，不能扩展为下载入口。

目标文件已在网盘定位或转存成功后，立即读取[客户端操作流程](references/client-workflow.md)，在客户端按路径、完整文件名和大小核对目标并提交下载，不继续探索下载命令或网页入口。客户端操作受阻时按该流程恢复；仍失败则保留现场并报告具体阻碍，不探索替代下载路线。用户明确要求改变下载方式时，说明超出本技能流程，再按新请求处理。

## 执行前检查与阶段推进

在首次公开检索或转存前，先读取[客户端操作流程](references/client-workflow.md#先验证本会话的客户端能力)，用本会话实际可用的工具验证客户端观察与输入能力；已有任务则直接从该检查进入恢复。安装了客户端、磁盘空间充足或另一Agent曾成功，都不能代替本次自检。能力受阻时先报告，不先花数分钟搜片和转存。用户明确只要求检索或转存时，不要求下载能力自检。

只在阶段结果有证据后推进：客户端可操作 → 分享与版本已核验 → 目标已在网盘 → 本地准备通过 → 客户端任务已出现 → 完成与落盘核对。某阶段失败不重走已经成功的阶段；用户要求重新找资源时重做检索，但仍先检查下载能力，并保留原任务与文件。`prepare`返回冲突时读取具体原因，不删除`.qfetch.json`或另建目录来强行获得`ready`。

检索预算按实际时间核对，不用调用次数估计；达到上限后只收束已取得的结果，不再打开新来源、补查新分享或重置计时。某个候选尚未核验通过时不能为“尽快下载”跳过版本证据。客户端恢复预算和检索预算分别计算，详见各流程；用户等待授权的时间单独记录。

## 多资源请求

一次请求可包含多个资源，由Agent整理清单并默认串行执行，每项沿用下文的单文件流程，完成核验或确认该项受阻后再处理下一项。用户提供影片列表时按作品身份去重，保留指定的不同版本；只有名称存在歧义时补充年份等信息，不能把同名作品合并。

“下载2026年豆瓣评分前十的电影”等条件型请求，由Agent先查询并解析为明确的影片清单，记录榜单来源、统计日期及采用的排名口径，再进入下载流程；本技能不内置榜单获取器。口径或作品身份无法确定时先澄清，不猜测下载对象。

- 每项独立使用[全网资源检索](references/web-search.md)的预算，榜单查询不占用单项资源检索预算；达到单项上限后不自动重试或重置预算。
- 某项未找到合格资源、分享失效或出现仅影响该项的失败时，记录原因并继续其他项；登录、客户端不可操作、目标盘未挂载或空间不足等共性阻碍，按既有流程恢复，仍受阻则停止后续下载并保留现场。
- 每个文件使用独立目录和现有任务记录；继续未完成清单时，核对已有文件及客户端原任务后复用，不重复下载。Agent维护各项状态，最终汇总已完成、失败、受阻和未执行项，给出来源、保存路径及失败或未执行原因；提交任务不等于完成。

## 资源定位

视频默认面向Jellyfin片库，搜索时优先尝试MKV；未找到合格资源时去掉格式限制，仍共用原检索预算。MKV是软偏好：按[资源自动选择](references/resource-selection.md)先满足画质、体积、字幕和播放兼容要求，条件相当时优先MKV，合格MP4仍可下载。格式以分享内实际文件名核验，不凭来源页标题判定；已有指定文件或原任务时直接复用。

以下流程每次处理一个文件。用户只给名称、要求全网找资源，或自己的网盘未找到匹配文件时，先读取[全网资源检索](references/web-search.md)，仅通过Google发现资源，打开结果页验证来源和分享后，按[资源自动选择](references/resource-selection.md)确定文件，再接入转存与下载。已有明确分享链接或原任务时直接核验复用。优先用官方`quarkclouddrive`技能完成账号内查重、元数据读取和分享转存；下载、暂停和恢复交给官方客户端。使用当前Agent提供的原生应用、辅助功能、截图或键鼠工具；不依赖特定厂商的工具名称或调用语法。先读取[客户端操作流程](references/client-workflow.md)，按已验证路径执行，用当前窗口核对每一步的结果。

## 定位与准备

按当前条件选择可靠且省步骤的方式：

| 当前情况 | 处理方式 |
|---|---|
| 只有资源名称、要求全网查找或网盘搜索无结果 | 按[全网资源检索](references/web-search.md)搜索并验证分享，不把自己的网盘搜索当作全网搜索 |
| 官方技能可用且已授权 | 优先用它搜索账号内文件、读取精确元数据及转存分享，遵循其当前说明 |
| 未安装官方技能 | 按[官方技能准备](references/official-skill.md)从可信来源自动安装并验证 |
| 官方技能未授权或授权过期 | 按[官方技能准备](references/official-skill.md)主动告知用户并引导登录；等待用户完成授权，不继续试探账号操作 |
| 安装失败、相应能力不可用，或用户明确不使用官方技能授权 | 说明原因后使用已登录客户端完成定位和转存，不循环安装或登录 |
| 文件已在客户端唯一定位或已有原任务 | 直接复用，不为遵循首选方式重复搜索或转存 |

安装成功不等于账号已授权，客户端已登录也不等于官方技能已授权。首次安装后必须检查授权状态；缺少授权时主动向用户说明需要完成登录，并按官方流程交互，不能静默切换客户端或探索其他认证方式。Google是当前唯一的公开资源检索通道；工具超时不等于Google不可用。停止前必须按[超时恢复流程](references/web-search.md#工具超时与页面状态恢复)检查已有标签页；DOM快照超时后停止重复调用，检查承载页面的浏览器是否全屏，退出全屏并重新获取原生窗口，用辅助功能和截图继续读取、操作已有结果。原生观察恢复后沿用该路径，不因退出全屏就重试故障快照。确认访问受阻或有限恢复仍失败时报告具体证据，不切换其他搜索引擎或网盘聚合搜索。已有分享与账号内查重不属于公开资源检索。

优先结构化操作是为了减少界面交互和获得精确元数据；不是假定所有账号、接口及版本都更快或更稳定。选择已满足本次需求的路径，不同时通过两种方式操作同一转存任务。分享中只转存所需文件，已在网盘存在则复用。视频候选按[资源自动选择](references/resource-selection.md)自动取舍：多个版本优先选择≤10GB的最高分辨率，只有一个合格候选时不受10GB限制，全部超过10GB时选择最低分辨率的合格版本。首个发现的结果不能直接视为唯一资源；不合格则在预算内继续查找，不因多个画质版本请求人工选择。作品身份无法确定时不猜测下载对象。

确认客户端已登录且桌面可操作。先按操作流程使用普通窗口验证一次搜索输入；读到窗口不等于能够输入，不将`noWindowsAvailable`直接解释为锁屏。窗口定位和输入失败先自动恢复，恢复后继续原步骤，不把人工点击作为常规流程。核对文件来源、完整文件名和可用的大小信息，优先取官方技能返回的精确字节数。官方技能文件ID不应直接当作客户端UI定位标识；在客户端按网盘路径、文件名和大小重新核对目标。能取得精确字节数时传入`--size`；只有“3.9GB”等约数时省略该参数，不编造精确大小。来源用账号别名与网盘文件路径或已核对的文件ID标识，不保存Cookie、提取码或签名URL。

检查客户端是否已有同一来源、同一目标目录的任务；有则继续原任务。确认目标盘已挂载，再创建每个文件独立的目录。`SKILL_DIR`是本技能实际所在目录，由Agent解析；在终端中运行：

```bash
python3 "$SKILL_DIR/download.py" prepare --directory "$DIR" --filename "$FILENAME" --size "$BYTES" --source "$SOURCE"
```

脚本只检查本地文件、空间和任务记录，不控制UI或下载。已知精确大小时检查目标盘完整文件大小加64MiB；未知时仅检查最低余量并返回`free_bytes`，Agent必须结合客户端显示的大小保守估算所需空间，不能将`ready`当作空间充分的证明。若客户端另外使用缓存盘，还需核对该盘空间。临时文件大小不是下载进度。

- `ready`：可提交客户端下载任务，尚未启动下载。
- `existing_task=true`仅表示本地登记已存在，不证明客户端下载任务已提交。先检查客户端：任务存在则复用；仍停在目录选择器则继续该对话框；确认没有任务、最终文件及临时文件时，可以继续首次提交。存在临时文件但找不到任务时先排查，不重复下载。
- `file_present`：只表示最终文件存在；已知精确大小时也要求大小相同。先核对来源和客户端记录。
- `needs_attention`：保留现场，处理具体原因，不另建目录规避冲突。

## 下载与完成

按照操作流程选择保存目录，确认任务出现后持续观察。暂停、恢复和失败处理只操作本次任务；不使用“全部暂停/开始”。窗口或输入异常时先执行流程中的恢复步骤；模态窗口需单独激活，增量状态不变时用完整状态与截图核对操作是否已生效，避免重复提交或反转暂停状态。仍不可操作时一次性报告具体环境阻碍并保留现场；只有登录失效、确实锁屏或必须由用户完成的系统确认才请求必要协助。

需要查看本地文件时运行：

```bash
python3 "$SKILL_DIR/download.py" status --directory "$DIR"
```

进度、速度和暂停状态以本次客户端任务为准。只有在“已完成”中核对了同一文件、来源和保存目录后，才运行：

```bash
python3 "$SKILL_DIR/download.py" check --directory "$DIR" --client-completed
```

`complete`表示客户端完成、最终文件已落盘且没有残留下载临时文件。只有`size_verified=true`才表示精确字节大小也核对通过；未知大小时该值为`false`，报告实际落盘字节数和未验证项。它不证明内容校验和或播放经过验证。要求下载完成时持续跟进到完成或明确阻碍；报告实际状态和路径，不承诺会话结束后自动监控。

本技能不接管旧网页脚本的`.part`文件；旧任务与文件保持原样。客户端升级后先验证当前步骤的含义和结果，必要时适配当前步骤，不照搬旧坐标或重新探索整条路线。
