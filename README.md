# QFetch

[QFetch](https://github.com/forestyoung23/qfetch)（Quark Fetch）：让Agent通过Google查找资源，验证夸克分享，再通过夸克客户端下载到指定目录。支持单个资源或资源清单，多项请求由Agent默认逐项串行处理。

每个文件的唯一下载路径为：**Google搜索或复用已有来源 → 验证分享与文件 → 检查原任务与空间 → 客户端下载 → 核对完成与落盘**。暂停与恢复使用客户端原任务。清单理解与逐项执行由Agent负责，项目不包含独立批量调度程序、网页下载器、备用路线或Jellyfin操作。

下载必须直接操作夸克客户端。官方技能的`download`命令及下载指引不适用于QFetch流程；目标定位或转存成功后立即交接客户端，不尝试CLI下载、获取直链、网页/API下载或登录网页版网盘点击“下载”唤起客户端。客户端恢复仍失败时报告具体阻碍，不探索替代下载路线。

## 使用条件

- 已登录的夸克客户端，当前验证macOS夸克7.4.2.1020、内置网盘2.5.40。
- 能观察和操作原生窗口的Agent；可使用辅助功能、截图或键鼠，不绑定某个Agent的工具API。
- Python 3.10以上，无第三方包。`download.py`只检查本地任务和文件，不启动下载。
- 账号内搜索、元数据读取和分享转存优先使用官方`quarkclouddrive`技能；未安装时从可信官方来源自动安装。不可用时使用客户端，实际下载始终走客户端。

按可靠性、可用性与操作成本选择文件操作方式，已有结果或任务直接复用。安装成功后还需检查账号授权；未授权时主动引导用户完成官方登录，等待授权成功后继续。客户端已登录不能代替官方技能授权；用户明确不授权或安装、能力不可用时可使用已登录客户端。[官方技能准备](skills/qfetch/references/official-skill.md)给出发现、安装及交接步骤。

技能入口给出完成标准，[客户端操作流程](skills/qfetch/references/client-workflow.md)固定已验证的搜索、下载、目录选择、暂停及恢复路径。客户端升级时以当前控件含义和实际结果适配，避免盲用旧坐标。

公开资源检索当前只使用Google，不使用其他搜索引擎、网盘聚合搜索或资源站内搜索。可打开Google结果页及其中的分享入口核验；工具超时后先检查并复用已有标签页。DOM快照超时后停止重复调用，检查浏览器全屏状态，退出全屏并重新获取原生窗口，用辅助功能和截图继续操作已有结果；原生观察恢复不代表DOM快照已修复。此恢复流程不新增Playwright依赖。每次异常最多两轮恢复检查，确认访问受阻或恢复仍失败后报告具体阻碍，不自动切换渠道，也不将工具超时直接归因为Google不可用。默认最多5分钟、6次查询、10个候选来源页，任一上限达到即停止检索：有合格候选则自动选择并继续下载，没有则报告未找到；不自动开启新一轮。恢复耗时与补发查询仍计入原预算。账号内查重和已有分享不受公开检索通道限制；下载仍使用夸克客户端。详见[资源检索](skills/qfetch/references/web-search.md)。

视频默认按4K→2K（1440p）→1080p自动选择：有多个合格版本时，优先选择≤10GB的最高分辨率；只有一个合格候选时直接选择，不受10GB限制；全部超过10GB时选择最低分辨率的合格版本。同档按信息可信程度、字幕及播放兼容条件、体积自动取舍，无需人工挑选。10GB采用十进制单位，仅用于版本比较；实际磁盘空间仍须充足。不合格资源继续查找，首个搜索命中不能直接视为唯一资源。完整规则与示例见[资源自动选择](skills/qfetch/references/resource-selection.md)。

视频搜索默认优先尝试MKV，未找到合格资源时去掉格式限制，共用原检索预算。画质、体积、字幕与兼容条件相当时优先MKV，合格MP4仍可下载；不为MKV降低分辨率、牺牲字幕或播放兼容性、选择更大的文件或突破原体积取舍。格式须从分享内实际文件名核验，MKV后缀不代表Jellyfin客户端一定能直接播放。已有指定文件或下载任务直接复用。

## 下载前能力检查

先验证当前Agent会话能够观察并操作夸克客户端，再进行搜片和转存。客户端已安装或其他Agent曾成功不代表当前会话具备控制能力。自检通常不超过90秒；客户端主动恢复最多两轮、3分钟，失败后保留现场并报告。此时不通过重新搜片、探测内部端口或临时编写截图器继续空转；正常下载等待不受恢复预算限制。

截图失败只证明捕获失败，不直接断言权限原因或承诺重启必定修复。分辨率必须有文件名或元数据等证据，不能由文件大小推断；检索5分钟到期后不再追加“快速核验”。这些规则针对失败会话的耗时与错误推进，尚未证明ZCode端到端下载成功率已提高。

默认视频候选使用`select_resource.py`进行本地选择，候选JSON区分页面宣称、文件核验证据、精确大小与保守上界。脚本不联网、不转存或下载；候选模板及状态说明见[候选记录与本地选择](skills/qfetch/references/resource-selection.md#候选记录与本地选择)。选择结果不会替代分享核验、空间检查或本地完成核对。

## 安装

```bash
python3 install.py
python3 install.py --upgrade
```

默认安装到`$CODEX_HOME/skills/qfetch`，未设置时为`~/.codex/skills/qfetch`。其他Agent可指定其技能目录：

```bash
python3 install.py --target /实际Agent技能目录/qfetch
```

安装器复制完整技能目录；更新先备份旧代码。下载数据放在技能目录之外，含任务记录的安装目录不会被自动升级。旧客户端任务继续在原客户端处理；旧网页脚本的`.part`和记录保留，不自动迁移。

## 使用

向Agent提出：

> 使用 qfetch，使用Google查找《资源名称》，找到匹配的夸克分享并下载到 /我的下载目录，完成后告诉我来源和保存路径。

也可以直接提供夸克分享链接，跳过资源发现。

多部影片可直接提供清单，例如：

> 使用 qfetch，将《影片A》（2025）、《影片B》（2026）下载到 /我的下载目录，每部使用独立子目录，完成后汇总结果。

也可提出“下载2026年豆瓣评分前十的电影”等条件型请求。Agent先查询榜单，确定来源、统计日期和排名口径，整理明确清单后逐部执行；技能不内置榜单获取器。清单按作品身份去重，每部独立使用检索预算，完成核验或确认该项受阻后再处理下一部。单部找不到资源等局部失败记录后继续；登录、客户端或磁盘等共性阻碍恢复失败时停止。继续未完成清单时核对并复用已有文件和原任务，最终汇总各部状态、来源、保存路径及失败或未执行原因。完整约定见[多资源请求](skills/qfetch/SKILL.md#多资源请求)。

每个文件使用独立的已存在目录。Agent先核对来源、完整文件名及客户端显示的大小，检查客户端是否已有任务，再运行：

```bash
python3 skills/qfetch/download.py prepare --directory /下载目录 --filename example.mkv --size 1000000000 --source 账号别名:/网盘路径/example.mkv
python3 skills/qfetch/download.py status --directory /下载目录
```

`ready`仅表示本地检查通过；`existing_task`仅表示本地登记已存在，并不证明客户端任务已创建。`.qfetch.json`记录来源、文件名和大小，重复请求复用；原任务存在时只恢复原任务。已知精确大小时，脚本检查目标盘完整文件大小加64MiB空余；仅有客户端约数时省略`--size`，脚本返回可用空间，Agent需按显示大小保守估算余量。不把临时文件大小当作进度；其他缓存盘还需结合客户端实际设置检查。

只有客户端“已完成”中核对了同一文件和保存目录，才执行：

```bash
python3 skills/qfetch/download.py check --directory /下载目录 --client-completed
```

`complete`表示客户端完成、最终文件已落盘且无残留下载临时文件；`size_verified=true`才表示精确大小也已核对。未知大小时报告实际字节数及`size_verified=false`，不表示内容校验和或媒体播放已验证。已有文件不会被脚本覆盖或删除。

## 实测与边界

2026-10-26，同一账号、同一4,164,241,147字节（3.88GiB）文件：客户端下载显示41.6–42.9MB/s，连续40秒落盘采样约40.99MiB/s；在73.9%暂停后恢复，最终完整落盘，大小正确。前65MiB与先前网页下载数据一致，已记录本地SHA-256；没有云端整文件校验和可供比对。

客户端路径已验证一次GB级文件下载与普通暂停恢复，未验证客户端重启后的续传或其他操作系统。后续排查发现，本机全屏窗口曾出现“可读取但无法输入”的问题；退出全屏后恢复。对“前往文件夹”重新获取模态窗口、直接设置路径后，已自动完成一次1,048,183字节小文件的目录选择、下载和落盘核对，全程无需人工点击。流程默认普通窗口，固定恢复顺序，失败后报告具体环境阻碍。此结果尚不代表长期无人值守、所有Agent或其他显示器配置均已验收。

2026-10-26另一次4,324,323,426字节电影文件实测：对目录选择器单独执行置前/激活后，“打开”从禁用变为可用；完成指定目录下载，在35.0%暂停后恢复原任务，客户端下载显示约37.7–41.5MB/s。完成列表、打开所在文件夹与本地精确大小核对一致，没有临时文件残留。媒体元数据读取及开头、中段、结尾各5秒的视频和双音轨解码通过，已计算本地SHA-256，未做云端校验和比对或全片解码。恢复流程已加入客户端指引。

该案例还观察到页面路径与文件列表、增量辅助功能状态不同步；处理方式是等待内容就绪，必要时读取完整状态并用新截图核对，再重新定位控件。不能只激活主窗口而忽略模态对话框，也不能因一次旧状态读数重复点击暂停/恢复。当前证据支持本机该环境下的完整流程及普通暂停恢复，不等于跨版本、重启续传或长期无人值守均已验证。
